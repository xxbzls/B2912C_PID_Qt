# 探头闭环控制上位机v1.0

Qt Widgets + KtB2900 IVI-C + 现有 PIDFunction。操作界面固定连接真实 B2912C，CH1 测探头电压、CH2 输出控制电流，支持 PID 和手动输出。先连接成功再启动。工程位于 `F:/B2912C_PID_Qt`。

## 五天运行后查询边界错误恢复（2026-11-14）

- 现场日志显示一次 `Voltage compliance` I/O错误后，恢复阶段的接口锁校验读到 `-420 Query UNTERMINATED`。这是前一条查询/响应边界未完成后又发送查询造成的通信状态错误，不是PID计算或曲线故障。
- 每次通信恢复现在先执行 Device Clear，再主动读取并清空仪器错误队列中的查询边界错误（-410、-420、-430、-440），之后才校验接口锁、通道分组、输出状态、反馈和实测电流。
- 主控制或恢复校验阶段若出现查询边界错误，不再立即结束，而是进入下一次 Device Clear。当前会话连续3次恢复失败后，程序不退出，而是保持运行、暂停PID，并每秒自动关闭失效的SDK会话、重新连接同一VISA地址、重新取得接口锁。
- 自动重连不复位仪器、不重新配置输出，也不自动改写电流；单纯网络中断且仪器未重启时，B2912C会按已配置的连续输出方式保持最后一次电流设定。只有确认序列号仍是原仪器、通道分组独立、硬件保护配置未变、应开启的输出仍开启、反馈/实测电流仍在限值内后，才用新反馈继续闭环；中断期间不累积PID积分。
- 自动重连没有次数上限，用户仍可随时点击停止/断开。网络长期断开时软件无法读取反馈，安全依赖已经启用并读回的仪器硬件保护；真实保护触发、输出已经关闭、模块错误、不同仪器或反馈/电流越限不会自动重新开启输出，而是停止并报告。
- 清理只恢复通信事务边界，不复位仪器、不改写电流设定，也不会自动重新开启已经关闭的通道。

## 可设置到100 mA的电流限幅（2026-11-09）

- “电流限幅（±mA）”和“手动电流”现在允许设置到 **±100 mA**，但软件启动默认限幅仍为 **±10 mA**，升级后不会自动扩大原有输出。
- 限幅不超过10 mA时，CH2继续使用10 mA源/测量量程；限幅超过10 mA时，程序自动切换到100 mA源/测量量程。驱动封装和PID输出仍拒绝越过用户本次设置的限幅。
- 实测电流超过“用户限幅 + 检测容差”时立即故障关断。100 mA限幅对应0.1 mA检测容差，因此绝对值大于100.1 mA时触发瞬时过流保护。
- 提高限幅前必须确认负载、接线、接插件及CH2电压上限能够承受相应功率。程序不会因为提高电流限幅而自动提高CH2电压上限。

## 可设置的探头电压关断阈值（2026-11-09）

- “控制参数”新增“探头保护阈值（±V）”，默认 **±15 V**，可在停止状态设置 **0.1～15 V**。实际判断使用绝对值，正向或负向超过所设阈值都会进入故障关断；恰好等于阈值允许继续运行。
- 开始 PID 或手动输出后锁定该参数。目标电压仍限于 ±10 V，并且不能超过用户设置的探头保护阈值。
- CH1 使用 20 V 测量量程，程序自动把仪器硬件合规后备关断设为 **±17 V** 并读回核对；读回不一致时拒绝启动。默认 15 V 软件阈值能够先被检测，同时保留 2 V 的独立硬件余量。
- 故障信息显示本次实际阈值。软件超限、仪器到限或测量异常仍按原流程关断两通道，且不会自动重新开启。

## 缩放后继续显示最新曲线（2026-11-08）

## 长时间运行延迟恢复与通信清理（2026-10-30）

- 期望采样周期仍默认为 100 ms。一次测量成功但实际周期超过 `max(1 s, 5×期望周期)` 时，不再立即终止控制：记录延迟告警、保持上一条 CH2 电流指令、读取并检查实测电流和仪器保护状态，本轮不调用 PID，因此不会补算延迟期间的积分。
- 后续有效周期恢复正常时，记录恢复日志并使用新反馈继续控制。连续 3 次超过上述阈值，或单次周期达到 `max(5 s, 20×期望周期)`，进入关断保护。
- VISA/I/O 调用直接报错、连接丢失、控制锁丢失、反馈越限、实测过流、合规或仪器到限关断仍立即进入原有保护，不等待连续次数。
- `INIT:ACQ → *OPC? → FETCH` 测量事务现在维护未完成查询标志。等待或读取失败后，关断流程会先执行 Device Clear 恢复通信边界，再依次尝试 CH2 OFF、CH1 OFF、状态读回、释放控制锁和关闭会话；不会写入 0 mA 或自动重新开启通道。
- 仪器错误队列条目在日志中明确标注“可能早于当前操作”，避免把此前遗留的 `-241` 错误简单归因于释放控制锁。
- Release 编译、测量事务、延迟恢复、保护、持续监测及完整 16 项离线回归通过。专项测试验证一次约 1.1 s 的成功延迟可恢复，连续 3 次延迟会关断。测试没有连接真实 B2912C，仍需进行长时间实机验证。

Kp、Ti、Td、电流限幅、仪器设置等仍需停止后修改。启动前直接填写目标即可；手动输出和仅 CH2 电流测试期间不提供在线目标应用。停止、故障或关闭时取消尚未应用的目标，下次启动使用输入框中的启动参数。

Release 和 Debug 均已编译，12 组离线测试通过。`--target-test` 覆盖积分保持、正负目标及范围校验、跨线程应用、持续输出、停止取消、故障保护及界面操作；`--plot-test` 覆盖目标阶梯线和历史悬停数据。结果见 `tests/results/target-test.txt`、`target-regression.log`。本功能尚未进行真实仪器带载验证。

## 控制量与单位（2026-10-08）

CH1 的位移测量电路电压直接作为反馈，目标也以 V 输入，范围 -10～+10 V。电压误差为 `目标电压 - CH1探头电压`；PID 输出为最终控制电流（mA），限幅后除1000转换为A，通过IVI-C下发CH2。Kp单位为mA/V，Ti和Td单位为s。界面及计算流程已移除位置换算a、b，曲线和悬停数据显示探头电压、目标电压及电压误差（V）。

例如：目标0 V、反馈1 V、Kp=2 mA/V、Ti=Td=0、控制方向+1时，PID输出-2 mA；若电流限幅为1 mA，实际下发-1 mA。此例只说明单位换算，不是实际装置的整定参数。CH2电压合规上限与CH1目标电压是两个不同参数；程序默认读取并保留仪器的CH2上限，不再用界面默认5 V覆盖。

## 电流限幅与仪器电压设置（2026-10-08）

- 电流限幅可设置到±100 mA，默认仍为±10 mA；PID输出及手动设流均受用户本次设置的边界约束。
- 主界面的“CH2 电压上限”显示仪器读回值，无需填写。连接只读取真实仪器；每次启动前重新读取CH2上限，随后复位、恢复原值并读回核对，通过后才开启输出。
- 需要修改时，展开“高级仪器设置”，勾选“覆盖仪器 CH2 电压上限”后输入。覆盖默认不勾选，输入框中的5 V不生效；手动覆盖范围仍为0.1～20 V。
- 未勾选覆盖时保留仪器现有有效值（大于0、至210 V），不会自动升高它。若客户已在仪器设置更高值，程序会保留该值；保留设置不代表已验证其适合负载。
- 读回0 V、无效值、读写失败或恢复核对失败时拒绝开启输出。运行触及合规上限时提示原因并停止、尝试关断；不会为了达到目标电流自动增加电压上限。
- 电流限幅不能据此推算负载所需电压。程序沿用仪器CH2电压上限，并不保证任意负载都能达到所设电流。
- IVI仿真驱动新会话返回初始0 V，程序仅在`Simulate=true`时将模拟CH2初始化为手册默认2 V。真实仪器没有这个自动赋值行为。

## 12 Ω 电阻闭环测试

闭环路径：CH2电流 → 电阻两端电压 → CH1测量 → Qt PID → 下一次CH2电流。这能验证电压反馈和电流控制链路，不能替代客户装置的机械响应测试。

### 接线

两路输出关断后接线。这里按只有一个无源12 Ω电阻、没有其他供电或接地回路的测试接法：

```text
CH2 FORCE HI ──┬────[ 12 Ω ]────┬── CH2 FORCE LO
              │                │
CH1 FORCE HI ──┘                └── CH1 FORCE LO
```

CH2位于后面板，CH1位于前面板。两路HI接电阻同一端，两路LO接另一端。使用FORCE插孔，当前2线接法不接SENSE、GUARD；可用万用表直流电压档并联到电阻两端，红表笔插V/Ω孔、黑表笔插COM。[官方快速参考：面板与通道端子](https://www.keysight.com/fi/en/assets/9925-01428/installation-guides/B2900C-CL-Series-Precision-Source-Measure-Unit-Quick-Reference.pdf)

程序在完整模式把CH1设置为源0 A、测电压，因此CH1测量时也会开启通道；不要把CH1手动改成0 V电压源并联在电阻上。

### 起始参数

| 参数 | 本次12 Ω测试值 |
| --- | --- |
| 通道配置 | 固定 CH1 测探头电压、CH2 输出电流，连接真实 B2912C |
| VISA地址 | 从Connection Expert复制；此前验证过 `TCPIP0::169.254.215.212::hislip0::INSTR`，IP变化时重新确认 |
| 目标电压 | 0.0120 V（12 mV，理论对应约1 mA） |
| 电流限幅 | ±2.0000 mA |
| 手动电流 | 1.0000 mA，用于先检查CH1反馈 |
| Kp | 20.0000 mA/V |
| Ti | 0.5000 s |
| Td | 0 s |
| 控制方向 | +1 正电流使探头电压增大 |
| CH2电压上限 | 2 V；读回是2 V则保持；否则在高级设置中明确覆盖为2 V |
| 测量积分时间 | 0.1 NPLC |
| 期望采样周期 | 100 ms |

先在这个完整模式点击“开始手动输出”：CH2输出电流应接近1 mA，CH1反馈和万用表应接近+0.012 V（实际值受电阻误差和测量误差影响）。如果反馈接近0或符号相反，先停止并核对接线。确认后停止并关断，再点击“开始PID闭环输出”。观察反馈接近0.012 V、稳态电流约1 mA；到位后PID持续保持输出，直到停止。

上述PI参数仅为电阻实验起点，已用12 Ω理想电阻模型核对正负12 mV目标收敛及2 mA限幅；尚未由本次修改完成真实闭环验证。如果出现振荡，先停止并降低Kp或增大Ti。正目标验证后可停止、把目标改成-0.0120 V再启动，核对反向电流。当前2 mA限幅对应12 Ω上的最大约24 mV，不应填写2 V等不可达目标。

### 如何判断触及电压上限

仪器面板CH2区域的大号V读数是实测端电压，右侧Limit (Compliance)是设定上限。在“仅CH2电流测试”模式，Qt也显示CH2端电压；完整PID模式的反馈值来自CH1，本次并联电阻接法下就是电阻两端电压。程序还读取仪器合规状态；触及时日志会指出通道，并停止、尝试关断。不能仅根据电流没达到目标就认定电压受限。

## 先连接，再控制（连接时无需负载）

VISA 地址输入框默认填入 `TCPIP0::169.254.215.212::hislip0::INSTR`，未连接时可以修改。

填写完整 VISA 地址，点击地址右侧“连接电源”。程序在后台用 IVI 驱动建立并保持连接，读取型号、序列号、固件及CH2电压上限，并取得本机设备锁和仪器接口锁；成功时状态栏显示绿色“已连接”，两个启动按钮才可用。连接使用 `InitWithOptions` 的 `reset=false`，不配置或开启输出，保留仪器原有输出状态。连接期间仪器面板会因接口锁而锁定；在软件中断开连接后释放。

点击“开始PID闭环输出”或“开始手动输出”时使用同一连接，复位、配置并开启所需通道。“停止并关断”只关闭CH2、CH1并核对状态，不写0 mA、不修改最后一次电流设定；保持连接，可修改参数后再次启动。点击“断开连接”才释放会话；地址在连接期间锁定，修改前先停止并断开。关闭窗口时先停止输出、断开连接，再退出，同样不改电流设定。下一次启动仍会重新配置输出，不会直接恢复上次电流。

空闲期间每秒读取一次通道状态检查通信；通信错误或运行错误会退出会话并禁用启动，需重新连接。通信中断时无法保证硬件已关断，应查看仪器面板。IVI 驱动仿真同样先连接模拟驱动，界面明确标注仿真。

## 探头电压 PID：实机初次操作

1. CH1 FORCE HI/LO 接位置探头电压及其参考端；CH2 FORCE HI/LO 接接受控制电流的装置。按仪器和装置手册确认参考端、隔离及接地，不能凭软件默认假定两路 LO 可任意短接。
2. 直接输入所需的目标探头电压，例如0 V；软件直接比较CH1测得电压和目标电压，不再换算成位移单位。
3. 填入 VISA 地址并点击“连接电源”，确认显示 B2912C 型号及CH2上限读回值。默认保留仪器上限，设置较小的电流限幅；点击启动会保存上限、复位、恢复并核对，然后启用两个通道。
4. 先用小电流“手动输出”确认正电流使CH1探头电压增大还是减小，并选择对应控制方向。手动电流是实际物理电流，不乘 PID 方向系数。停止后修改参数，再进行下一次试验。
5. 方向确认后选择 +1 或 -1，先设 Ti=0、Td=0，从小 Kp 开始；需要消除稳态误差时再引入积分。目标电压可在PID运行中点击“应用目标”更新，其他参数仅允许停止后修改。
6. 观察实际周期、电压误差和输出电流。达到目标后保持闭环，可能需要非零电流维持位置。停止会直接关断输出，不等于保持当前位置。

CH1 使用“源 0 A、测电压”：10 nA 源量程，20 V 电压测量量程，17 V 仪器硬件后备关断；软件探头保护默认 ±15 V并可向下调整。CH2根据用户限幅自动选择10 mA或100 mA量程，软件绝对限幅为 ±100 mA、默认限幅为 ±10 mA。NPLC 当前默认 1.0；调大可增加积分时间，也会降低更新速度。

调用链：`readVoltage()` → `VoltagePid::step(feedbackV, dt)` → `setCurrent(mA/1000)`。误差为`targetV-feedbackV`（V），返回值是最终电流（mA），不是增量。驱动设流单位为A，反馈测压单位为V。

动态加载使用官方 `KtB2900.h` 的 `decltype` 获取函数指针类型，仍然调用 IVI-C 接口；不需要把 MSVC 的 `.lib` 链接进 MinGW，也未改成手写 SCPI。

## 测试和边界

### 运行保护（2026-10-08）

保护默认启用；主界面可修改探头电压阈值和本次电流限幅。规则如下：

| 检测项 | 触发规则 | 适用范围 |
| --- | --- | --- |
| CH1 探头电压 | 绝对值超过界面阈值即停；默认±15 V、可向下调整，等于阈值允许；NaN/无穷值也停；仪器另有±17 V硬件后备关断 | 完整模式的 PID 和手动输出；仅 CH2 测试不读取 CH1 |
| CH2 实测电流超限 | 绝对值 > 配置电流限幅 + 检测容差；容差为 max(0.005 mA, 限幅×0.1%)；单次采样即停，启动期间也有效 | 两种功能模式 |
| CH2 电流持续偏差 | 实测与设定的差值绝对值 > max(0.02 mA, 设定值绝对值×5%)，连续至少3个异常样本且持续 max(0.5 s, 3×期望周期) 后停机；启动前0.3 s仅跳过此项 | 两种功能模式 |
| 设流命令 | 控制算法和驱动封装都限制在用户配置的±限幅内，软件绝对上限±100 mA；下发后读回核对，读回不一致也停机 | 两种功能模式 |
| 仪器到限关断 | 每次启动配置两路 `OUTPUT_PROTECTION_ENABLED=true`、`OUTPUT_AUTO_ON_ENABLED=false`、`OUTPUT_AUTO_OFF_ENABLED=false`，读回核对后才开启输出 | 仪器端关断达到合规上限的通道，软件发现后关断两路 |

检测容差用于避免测量噪声误报，不会放宽下发电流限幅，也不是精度保证。持续偏差的计时不会因PID改变设定电流而清零；只有读数恢复或新一轮手动启动才重新开始。CH1越界检测位于PID计算和下一次设流之前，CH2电流读回后立即检测，异常时不再进入下一轮控制。

仪器到限关断是仪器自身的合规保护。在本工程电流源模式下，CH2按选定的电压合规值关断；它不等于本机软件的实测电流比较器。CH1使用17 V硬件后备关断，软件阈值默认15 V。轮询同时读取合规状态、Questionable寄存器的输出保护位（CH1 bit2、CH2 bit3）及输出开关状态；不会仅因保护后合规状态消失而漏报。关闭自动开启输出，防止后续测量触发重新通电；关闭测量完成自动关断，使正常输出可持续。

#### 多程序争用

- 本机新版程序使用固定名称的Windows内核互斥对象，改名或从其他目录启动也不能打开第二个正常控制实例。
- 连接真实仪器后按序列号取得设备互斥锁，统一处理不同VISA地址别名；随后通过 `SystemRequestLock` 取得仪器I/O接口锁。已有持有者、申请失败或运行中所有者改变时拒绝启动或停机。不会抢占、强制清锁。
- 正常停止保留连接和锁；断开或异常清理后释放。进程退出会释放本机内核对象。仪器LAN锁在检测到连接断开时释放。
- **边界：仪器接口锁并不是VISA会话独占锁，同一接口上的其他程序可能仍能访问。** 它也会锁定面板（包括Local键）。旧版程序及Interactive IO不参与本机新版互斥，实验时须先退出这些控制会话。没有把IVI的线程锁 `LockSession` 当作跨程序锁使用。[官方SCPI手册，304–306页](https://www.keysight.com.cn/cn/zh/assets/9925-01426/programming-guides/B2900C-CL-Series-Precision-Source-Measure-Unit-SCPI-Command-Reference.pdf)

#### 触发后如何恢复

故障触发后锁存本轮错误，退出控制，先向CH2、CH1发送关闭输出命令，再核对两路关闭状态。关断前后均不写0 mA，保留最后一次电流设定。即使其中一路关断失败，也继续关闭和检查另一路。随后断开连接，不会自动重启。先按日志排除原因，再重新连接并手动启动。只有确认是CH2电压合规不足且新值适合负载时，才调整CH2电压上限；CH1反馈越界或实测过流不能通过提高这个上限解决。正常点击“停止并关断”也使用相同的关断顺序，但保持连接，可直接修改参数后再启动。

软件检测依赖采样和通信，无法保证在两次采样之间或PC/网络故障时立即关断；仪器到限保护仅覆盖其合规触发条件，不能替代失联急停。
